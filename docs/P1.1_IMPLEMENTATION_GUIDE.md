## 実装案 A: TTL キャッシュ（Spotify fetch）

**実装場所:** `backend/core.py` の `fetch_playlist_tracks()` 関数

**手順:**

1. `cachetools.TTLCache` を使用
2. Playlist URL を正規化（`?si=...` パラメータ削除）
3. キャッシュ TTL = 6時間（ローカル） / 24時間（本番）

**コード例:**

```python
from cachetools import TTLCache
import time

# グローバルキャッシュ
_spotify_cache = TTLCache(maxsize=1000, ttl=6 * 3600)  # 6時間


def fetch_playlist_tracks(playlist_id_or_url: str) -> Dict[str, Any]:
    # URL 正規化
    normalized_key = normalize_spotify_url(playlist_id_or_url)

    # キャッシュ確認
    if normalized_key in _spotify_cache:
        logger.info(f"[CACHE HIT] {normalized_key}")
        return _spotify_cache[normalized_key]

    # キャッシュなし → 取得
    logger.info(f"[CACHE MISS] {normalized_key}")
    result = _fetch_from_spotify(playlist_id_or_url)

    # キャッシュに保存
    _spotify_cache[normalized_key] = result
    return result
```

**期待効果:**
- Cold Run: network_ms = 450ms（変わらず）
- Warm Run 1: network_ms = 10-50ms （最大90%削減）
- Warm Run 2: network_ms = 10-50ms

**実装時間:** 10-15分

## 実装案 C: Rekordbox マッチング最適化（xml_ms）

**実装場所:** `backend/rekordbox.py` の `mark_owned_tracks()` 関数

**手順:**

1. マッチングキー（ISRC, artist+title）をハッシュセット化
2. 4段階マッチを fail-fast で実装
3. インデックスデータ構造（dict）を事前構築

**コード例:**

```python
def mark_owned_tracks(tracks, rekordbox_xml_path):
    # XML パース
    rb_collection = parse_rekordbox_xml(rekordbox_xml_path)

    # インデックス構築（事前）
    isrc_index = {t["isrc"]: t for t in rb_collection if t["isrc"]}
    key_index = {normalize_key(t): t for t in rb_collection}

    # マッチング（fail-fast）
    for track in tracks:
        # 段階1: ISRC
        if track.get("isrc") and track["isrc"] in isrc_index:
            track["owned"] = True
            track["owned_reason"] = "isrc"
            continue

        # 段階2: exact
        key = normalize_key(track)
        if key in key_index:
            track["owned"] = True
            track["owned_reason"] = "exact"
```

## Q&A

**Q: 複数の実装案を同時に進められる？**
A: Yes. backend/frontend は独立なので並列可能。ただし計測テストは順序は影響しない。

**Q: 改善効果が出ない場合？**
A: `[PERF]` ログで改善前後を比較。改善が反映されてないなら implementation 見直し。

**Q: キャッシュはどこに保存？**
A: 最小: インメモリ（`cachetools.TTLCache`）。本番: Redis/Memcached 検討。
